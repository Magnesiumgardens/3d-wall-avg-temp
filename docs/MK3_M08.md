# Selected MK3 / M08 cases

The user selected `MK3_watertight.STEP` for geometry and these two separate BC
cases:

| Source filename | Temperature column | Interpretation to retain |
| --- | --- | --- |
| `M08_ALT30_A00_B0_base_Iso_5spe_2_redo` | `temperature` | Uniform 300 K fixed-wall case; heat flux is a separate field. |
| `M08_ALT30_A00_B0_base_Adiab_5spe_9` | `wall-temperature` | Adiabatic wall-temperature case, approximately 1,754–2,690 K. |

The user confirmed coordinates in **meters** and temperatures in **Kelvin**.
Use `--coordinate-unit m --temperature-unit K` explicitly for both cases; these
are also the tool defaults. This is user confirmation rather than independent
verification of CFD source metadata. Pressure and heat-flux units/sign conventions
have not been confirmed. No heat-flux loads or convection coefficients are derived.

The updated reader supports both the seven-column isothermal export and the
eight-column adiabatic export. Select `--temperature-column temperature` for the
isothermal file and `--temperature-column wall-temperature` for the adiabatic file.
Do not combine their temperatures into one distribution or interpret either as
an independently calculated conducting-skin temperature.

## Inspection findings

The isothermal file has 27,459 rows; the adiabatic file has 27,458. Both contain
the same 27,457 unique coordinate triples. Among common node IDs, 5,704 identify
different coordinates between files. Do not join these cases by row order or
node ID; coordinate duplicates also require explicit handling.

The STEP declares meters and imports as one valid closed solid with 66 geometric
faces. These are not automatically 66 physical thermal panels, and a watertight
solid does not establish physical exterior-skin thickness.

A candidate rigid alignment was fitted between BC points and CAD geometry.
The reconstruction now checks all 27,457 unique source locations against finite
CAD faces. Median mapping distance is approximately 0.020 mm, 95th percentile
0.070 mm, and maximum 0.142 mm. All locations map within the default 0.5 mm
tolerance. This geometric agreement does not independently verify the intended
orientation or SOLIDWORKS selections. Source geometry is expressed in meters;
these residuals are reported in millimeters to make their small size readable.

## Accepted reconstruction route

Original surface connectivity has not been extracted from the binary Pointwise
project, and the user has no Pointwise access. A surface export from the original
meshing/solver software remains the preferred route if it becomes available;
ANSYS access alone does not decode a Pointwise `.pw` project. The user accepts proceeding with
a **validated CAD-based reconstruction** instead of an original-mesh area average.

This accepts the method, not an unverified mapping or numerical result. Before
reporting reconstructed area-weighted panel temperatures, the implementation must:

1. Check coordinate alignment and physical panel/face groups.
2. Define temperature interpolation onto a CAD surface tessellation or quadrature.
3. Handle duplicate source coordinates explicitly and avoid interpolation across
   unrelated nearby surfaces.
4. Report source-distance limits, unmapped areas, ambiguity, and area coverage.
5. Check reconstruction and integration sensitivity to refinement.
6. Label outputs as reconstructed CAD-surface averages, retaining original inputs.

The new `python -m paneltemps reconstruct` workflow implements this route with
finite-face projection, face-local interpolation, curved-surface quadrature,
coverage reporting, and two-level integration checks. See
[the implementation method and Windows commands](RECONSTRUCTION.md).
The original `--method area` command still requires supplied CFD triangles;
reconstruction has a separate entry point and distinct output method labels.
Candidate CAD faces/physical panel groups and SOLIDWORKS load selections remain
unverified until reviewed.

## Implementation validation

The code passes 43 automated checks, including exact linear-field surface means
and standard deviations on a CAD cube, constant-temperature preservation,
nonuniform sampling, curved-surface area, duplicate handling, shared edges,
ambiguous nearby surfaces, and two-case CLI exports. Windows Python 3.12 wheels
exist for the pinned CAD/numerical packages; execution was tested on Linux.

Both actual M08 cases were processed using the supplied STEP and transform.
With default thresholds, 63 of 66 candidate faces pass numerical checks in each
case; faces 5, 32, and 48 remain unresolved and their main averages stay blank.
Faces 5 and 48 lack sufficient supported area under the trim/support checks.
Face 32 exceeds the boundary extrapolation allowance. Supported quadrature area
is about 99.96% of total CAD area, but the acceptance tests apply to each panel,
so a large global coverage fraction does not hide a small failed face.
For the accepted isothermal rows, averages remain 300 K to floating-point precision.
These are reconstruction/software checks, not validation of a CFD solution or
an internal thermal prediction. Diagnostics retain conditional supported-area
statistics on unresolved rows for review.
